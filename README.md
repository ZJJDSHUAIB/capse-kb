# CAPSE 机场满意度知识库 · 问答与评估

把 9 份公开的民航满意度报告,变成**可查、可核、可评估**的知识库。

**核心不是"用了 RAG",是两件事:**

1. **每个答案都带出处** —— 数据从库里查出来,不是模型编出来,所以出处是现成的
2. **每个设计选择都有对照数据** —— 说"这样更好"之前,先跑出两个数

> **要证明的不是"我会用 AI",是"我能对 AI 应用的效果负责"。**

---

## 现在能做什么

问一句,答一句。**答案带来源;跨口径时自动标注。**

```
问:2025Q4 上海浦东国际机场的综合得分是多少
〔去向〕SQL
〔答案〕2025Q4 上海浦东国际机场:综合得分 4.23,排名第 5/42
〔来源〕capse.db / 综合得分 表,期次=2025Q4,机场=上海浦东国际机场

问:2023Q3 和 2025Q4 的上海浦东,哪个分高
〔去向〕SQL
〔答案〕2023Q3 上海浦东国际机场:综合得分 4.15,排名第 5/41
        2025Q4 上海浦东国际机场:综合得分 4.23,排名第 5/42
〔标注〕跨口径: ['6+30', '7+28'] —— 两期的尺子不同,数字不可直接比较
〔过程〕关键词表判不出 → 大模型判定「要数」

问:2024Q3 上海浦东国际机场的机场安检得分是多少
〔去向〕拒答
〔答案〕不回答。指标级(一级指标)数据只有 2025Q4 一期,问题涉及 ['2024Q3']

问:报告的测评指标为什么调整过
〔去向〕检索
〔答案〕/ 2024年度CAPSE测评指标变更说明/ … ●为响应民航局《提升千万级机场
        航班近机位靠桥率指导意见》,新增"靠桥率"指标;…
〔来源〕2024Q1-P05 = 2024Q1 第 5 页
〔过程〕检索用词:测评指标 调整 变更 修订
```

**每条答案都带"去向 / 来源 / 标注 / 过程"四样东西** —— 判错的、拿不准的、跨口径的,全部摊开给用户看。

## 快速开始

```bash
# 1) 配密钥(只有"问句改写"和"意图判断"两步用到大模型)
cp .env.example .env      # 然后填自己的 key

# 2) 问一句
python tools/ask.py
```

**依赖说明:**
- **问答这条链只用标准库**(`sqlite3` + `urllib`),不需要 `pip install` 任何东西
- 只有**从 PDF 重建全流程**才需要 `PyMuPDF`(fitz)和 `numpy`

## 系统结构

一条链,每一步都可以单独跑、单独测:

```
9 份季度报告 PDF
   │
   ├─ 切片入库 ─────────→ capse_chunks.jsonl   54 块
   │                       capse_meta.csv       9 期口径
   │                       capse_scores.csv     373 条综合得分
   │                       capse_indicators.csv 294 条指标得分
   │                              │
   │                       〔tools/build_db.py〕SQLite + 约束
   │                              ↓
   └─ 全文索引 ─────────→ capse.db
                          ├ meta 9 行 / 综合得分 373 / 指标得分 294
                          ├ chunk 54 行(真相源)
                          ├ chunk_fts(FTS5 trigram 索引)
                          └ 综合得分排名(视图,不存数据)
                                 │
                            〔tools/route.py〕路由
                                 │  ① 要数还是要话  ② 在库吗  ③ 跨口径吗
                                 │  └ 判不出 → 交大模型 〔route_llm.py〕
                                 ↓
                            〔tools/ask.py〕执行 + 验证 + 组装
                                 │  SQL 查表 / 检索查原文
                                 │  └ 事后验证:回来那几段话答得了这个问题吗
                                 ↓
                              带来源的答案
```

## 关键设计决策

每一条都是"**为什么不那样做**"。详细的写在 [`docs/`](docs/)。

| 决策 | 为什么 |
|---|---|
| **meta 表是唯一真相源**,chunk 文本只用来校验 | 同一个事实可以有多个副本,但只有一个是"用来取值"的。文本副本每次都要重新解析 = 每次都可能解析错 |
| **约束写在库里,不写在人心里** | 5 条非法插入实测被拦下。约束没生效 = 白写,所以必须拿真实非法数据撞一次 |
| **排名用视图,不建表** | 排名是派生量,存下来会过期而且错得看不出来。这是**一致性取舍,不是性能取舍** |
| **先做关键词检索,向量留到第 7 课** | 没有基线,"向量更好"这句话永远说不出口 —— 更好?比谁好?好多少? |
| **中文必须 `tokenize='trigram'`** | FTS5 默认的 `unicode61` 把整句中文当一个词,**搜索静默返回 0,不报错** |
| **"拒答"不是第三条路,是第一道闸** | 它是"数值型 × 数据不在库"的产物。当成并列选项,就会把库里有的数据也拒掉 |
| **规则只在不会错的地方出手** | 关键词表判错时**跟判对一样有把握**,所以判错根本不会升级给模型。有歧义的词一律删掉 |
| **答案必须带来源 —— 结构上强制** | 答案不是一个字符串,是带 `来源` 字段的结构。**没有来源的答案,在结构上就构造不出来** |
| **密钥不进仓库** | `.env` 被 gitignore;`.env.example` 进仓库。key 一旦进过 git 历史,删不干净,只能作废 |

## 已知问题与边界

**诚实说明,不藏:**

- **SQL 那一路的来源只能到"表名"**,回不到 PDF 页码 —— 第 1 课入库时没记页码。检索那一路是完整的(带页码)
- **2 个字的词搜不了**(trigram 索引要求 ≥3 字)。"删除""调整""口径"这类常用词全部落空
- **年度报告(2024年度)没进库**,文件名里没有季度编号,切片时被跳过
- **没有评估集,所以现在说不了"准确率是多少"** —— 只能说"这 10 道看着对"。这是第 6 课要解决的
- **不是有商业价值的产品**,是求职作品。技术实现保持入门级,不堆框架
