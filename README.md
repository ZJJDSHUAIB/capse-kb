# CAPSE 机场满意度知识库 · 问答 + 评估 + 报告

把 9 份公开的民航满意度报告,变成**可查、可核、可评估**的知识库。

**核心不是"用了 RAG",是三件事:**

1. **每个答案都带出处** —— 数据从库里查出来,不是模型编出来,所以出处是现成的
2. **每个设计选择都有对照数据** —— 说"这样更好"之前,先跑出两个数
3. **★ 它知道自己哪里不可信** —— 答不了的时候会说出来,而不是硬答一个

> **要证明的不是"我会用 AI",是"我能对 AI 应用的效果负责"。**

---

## 三个数

| | |
|---|---|
| **准确率** | **60/60**(60 道自建评估集,去向对 60/60) |
| **静默失败** | **0 道** —— 而这门课开始时是 **24 道** |
| **告警率 / 误报率** | **100% / 0%** —— 错了都出声,对了不乱报 |

> **⚠⚠ 这三个数有一个前提,必须写在旁边:**
>
> 它们是**三个开关全开**时量的 —— `--merge`(合并检索)+ `--gen`(生成层)+ `--retry`(重试循环)。
>
> ```bash
> python tools/score_eval.py --merge --gen --retry
> ```
>
> **★ 为什么这条前提非写不可(实测):** 有人照着下面的「快速开始」跑
> `python tools/score_eval.py`(**不带开关** = 第 5 课以来的基线),
> 得到的是 **41/60 = 68.3%**,而上面写的是 60/60 ——
> **他会以为项目坏了,或者以为这个数在吹。**
>
> ★★ 不带开关的那一档也是真数,而且它更该被看见:**它才是改进的起点。**
> 两档一起看,才知道后面那些工作值多少:
>
> | 跑法 | 得分 | 那是什么 |
> |---|---|---|
> | `score_eval.py` | **41/60 = 68.3%** | 基线:只有关键词检索 + 材料拼接 |
> | `score_eval.py --merge --gen --retry` | **60/60** | 全开:合并检索 + 生成层 + 重试循环 |

> **"静默失败"指:系统答错了,而且用户读完整段答案都发现不了。**
> 它是这门课从头打到尾的那一个东西。

**⚠ 但这三个数,不是直接量的 —— 它们是【先把量分数的尺子校准过】之后量的。**
**为什么那一步不能省,见下一节。**

## ★★ 我量过那把「量分数的尺子」

**系统跑到 60/60 的时候,我做了件不太常见的事:去量那把【给分的尺子】本身。**

做法很土 —— 拿**同一批答案**,让判分跑三次:

```
第1次  判错 [46, 48]
第2次  判错 [46, 47, 48]
第3次  判错 [40, 46, 48]

★ 同一批答案,三次判出来的错题【不一样】。
```

**再往下查,原因不在模型,在【判据有三个洞】:**

```
· "关键事实一致就算一致"    —— 名字对、数字没给,算不算?没写
· "数字"两个字明明在那儿     —— 少一个数字算不算?没写
· "多说了别的,不算错"       —— ★ 那【少说了】呢?没写
```

**补上之后,判分从【晃 ±1】变成【完全不晃】:**

```
旧提示词          58 / 57 / 57
补洞(第一版)      57 / 56 / 56   ← ★ 补过头了,误伤
补洞(定稿版)      59 / 59 / 60
★ 再把【能算的交给代码】   59 / 59 / 59   ← 不晃了
```

> **这件事的意义:在那之前,我不敢说"我的系统 60/60"——**
> **因为我不知道那个 60 里,有多少是判分给的面子。**

**★★ 顺带说一个反直觉的结果:校准之后分数【掉过】一次(60 → 59),而那是好事。**
**因为掉的那一分是假的。详见 [`docs/第9课_实验台账.md`](docs/第9课_实验台账.md) 第 11 课那一节。**

## 现在能做什么

### 一、问一句,答一句

**答案带来源;跨口径时自动标注;答不了时【出声并给提示】。**

```
问:2025Q4 上海浦东国际机场的综合得分是多少
〔答案〕2025Q4 上海浦东国际机场:综合得分 4.23,排名第 5/42
〔来源〕capse.db / 综合得分 表,…  → PDF 2025Q4 第9页

问:2023Q3 和 2025Q4 的上海浦东,哪个分高
〔答案〕… 2023Q3:4.15  2025Q4:4.23 → 2025Q4 更高
〔标注〕跨口径:['6+30', '7+28'] —— 两期的尺子不同,数字不可直接比较

问:2025Q4上海浦东国际机场的靠桥率排名第几
〔去向〕拒答
〔答案〕2025Q4 没有「靠桥率」这个指标 —— 我没有它的数据,不猜。
        我搜到「靠桥率」在 2024Q1~2024Q4 的报告里出现过 —— 那你要的是那几期吗?

问:2025Q4合肥骆岗机场综合得分是多少
〔去向〕拒答
〔答案〕「合肥骆岗机场」不在库里 —— 我不拿别的机场替你答。
        库里合肥的机场有:合肥新桥国际机场 —— 你要的是其中一个吗?
```

**每条答案都带"去向 / 来源 / 标注 / 过程 / 警告"** ——
判错的、拿不准的、跨口径的,全部摊开给用户看。

**★ 而走【检索】的那些题,答案不是把原文贴出来,是【真的回答】:**

```
问:2025Q4分吞吐量级服务测评里,1000万-1500万级机场综合得分第一是谁

〔答〕2025Q4—1000万-1500万级机场综合得分第一是无锡硕放国际机场,得分4.17
     (出处:2025Q4-P21)。
     另:宁波栎社国际机场 4.17(出处:2025Q4-P21)
     【此句由代码从材料里的得分表算出,不是读出来的】

〔过程〕检索用词:2025Q4 吞吐量 服务测评 1000万-1500万 机场 综合得分
        第1轮:材料5页 → ★ 分档排名漏了
          └ 已【算出来补上】(不重试 —— 能算的别问大模型)
```

**★★ 三件事都在这一个例子里:**

```
① 答案是一句话,不是 1390 字的原文堆 —— 而且每句带出处
② 系统自己发现"漏了一个并列第一"(★ 那是【算】出来的,不是感觉)
③ ★★ 它补的那句【标明了"这是代码算的"】——
   不让用户以为整句都是大模型读材料读出来的
```

### 二、出一份报告

```
python tools/make_report.py
→ docs/报告/上海浦东国际机场_2025Q4.md
```

**报告的结构里,【可信程度放在最前面】—— 因为用户从第一页读起:**

```markdown
## ★ 这份报告的可信程度
- 前四节的每一个数字都能追到出处(可回 PDF 页码)—— 硬查通过
- 第 5 节整节是【推断】,不是数据
- 本期数据里,同档(按吞吐量级)对比
```

**而它有一个别的报告生成器没有的部件:一道【查它有没有编数】的关卡。**

```
代码管   「说什么数」        ← 硬:三种比法都算好,每条带出处
大模型管 「怎么把数说成话」   ← 软:但它只能用手里的数
    再管 「下什么结论」       ← 软:而且【标明是推断】
代码再查 「数有没有出处」     ← 硬:报告里出现数据里没有的数 → 拦下
```

**★ 为什么不能全交给大模型:问答里它编一个数,用户可能追问;
报告里它编一个数,直接变成结论,没人会核。**

## 从头装起来(第一次拿到这个仓库)

> **★ 为什么需要这一节:** 仓库里**没有** `capse.db`,也**没有** PDF 原文 ——
> 它们按规矩都不进仓库(*「真相源进,能重建的不进」*)。
> 所以 clone 下来之后,要先**建一次库**。
>
> **⚠ 这一节原来没有。** 原来只有下面「装好之后」那四行 ——
> 而第一步 `python tools/ask.py` 就【必然失败】,因为它要连的库还不存在。
> 是有人真的 clone 到新目录、照着走了一遍才发现的。

```bash
# 0) 装依赖
pip install -r requirements.txt

# 1) 建库★★ —— 只要 CSV,【不需要 PDF,不需要联网】,几秒钟
python tools/build_db.py

# 2) 配密钥(只有"问句改写""意图判断""组织成话"几步用到大模型)
cp .env.example .env      # ★ 然后【必须】打开 .env,把 key 换成自己的

# 3) 验一下:把算出来的路径打出来,并且看在不在
python tools/paths.py
```

**★ 到这里就能问答了。** 默认档走**关键词检索** —— **不需要下载任何模型。**

```bash
python tools/ask.py --ask "2025Q4上海浦东国际机场综合得分是多少"
python tools/ask.py                      # 不带参数 = 跑一遍内置的演示问题
```

**⚠ 关于 `.env`:** 复制之后**不填 key 也能跑一部分**(SQL 查询、关键词检索),
但一旦走到需要大模型的那几步会报错。报错会说清是 key 的问题 ——
**这是专门加的一道检查,因为不加的话你会收到一个和 key 毫不相干的编码报错。**

## 装好之后:三件事

```bash
# 1) 跑评估集(60 道自建题)
python tools/score_eval.py --merge --gen --retry    # ★ 开关看着下面

# 2) 出一份报告
python tools/make_report.py

# 3) 换别的档跑
python tools/score_eval.py          # 基线档(不带开关)
```

**★ 三个开关分别是什么 —— 关着时是第 5 课以来的基线:**

| 开关 | 打开之后 | 代价 |
|---|---|---|
| `--merge` | 关键词 + 向量**合并检索**(RRF 融合) | ★ **第一次会下载模型(约 100MB)**,要等一两分钟 |
| `--gen` | **生成层**:让大模型作答,而不是把材料拼起来 | 每题一次调用 |
| `--retry` | **重试循环**:生成 → 诊断 → 做对应的动作 | 失败时才多调用 |

**★★ 不带开关的那一档不是"坏的版本"** —— 它是**基准**,而且它更该被看见:
两档一起看,才知道后面那些工作值多少(41/60 → 60/60)。

**依赖(见 `requirements.txt`):**

```
sentence-transformers   向量检索(★ 第 9 课加的,它是问答链的一部分,不是可选的)
numpy
openpyxl                读评估集 xlsx
PyMuPDF                 只有【从 PDF 重建全流程】才需要
```

**★ 调大模型 API 用的是【标准库 urllib】,数据库用【标准库 sqlite3】——
不额外引入 HTTP 库,别人 clone 下来就少一步装包。**(见 `tools/llm.py` 的注释)

**⚠ 一处修正(2026-09-22):** 这里原来写的是"问答和报告这条链只用标准库"——
**那句话是加向量检索之前写的,已经不对了。** 现在向量检索是问答链的一部分。

## 关键设计决策

每一条都是"**为什么不那样做**"。详细的写在 [`docs/`](docs/)。

| 决策 | 为什么 |
|---|---|
| **meta 表是唯一真相源**,chunk 文本只用来校验 | 同一个事实可以有多个副本,但只有一个是"用来取值"的。文本副本每次都要重新解析 = 每次都可能解析错 |
| **约束写在库里,不写在人心里** | 5 条非法插入实测被拦下。约束没生效 = 白写,所以必须拿真实非法数据撞一次 |
| **排名用视图,不建表** | 排名是派生量,存下来会过期而且错得看不出来。这是**一致性取舍,不是性能取舍** |
| **先做关键词检索,向量留到第 7 课** | 没有基线,"向量更好"这句话永远说不出口 —— 更好?比谁好?好多少? |
| **中文必须 `tokenize='trigram'`** | FTS5 默认的 `unicode61` 把整句中文当一个词,**搜索静默返回 0,不报错** |
| **"拒答"不是第三条路,是第一道闸** | 它是"数值型 × 数据不在库"的产物。当成并列选项,就会把库里有的数据也拒掉 |
| **规则只在不会错的地方出手** | 关键词表判错时**跟判对一样有把握**,所以判错根本不会升级给模型。有歧义的词一律删掉 |
| **答案必须带来源 —— 结构上强制** | 答案不是一个字符串,是带 `来源` 字段的结构。**没有来源的答案,在结构上就构造不出来** |
| **答案里不含"显示用的截断"** | 一个为终端显示做的 120 字截断,在第 6 课变成了判分依据 —— 5 道题的答案被它砍掉。**显示用的文本和判分用的文本不能是同一个变量** |
| **口径变了要标出来** | 2025Q1 起一级指标从 6 项变 7 项、去掉"行李服务"加"出港/进港服务"。**不知道这件事的报告生成器,会把跨年数据比错,而且看起来完全正常** |
| **同一页的多期,是一件【事】不是九件** | 库里 **83%** 的内容是"同一页在多个期"的重复,而检索把它们当成互相独立的候选。**这一课所有检索类失败,根都在这里** |
| **一份报告的价值不在"绝对不错",在"错了你能知道"** | 用户的损失不是"数字错了",是**他不知道自己手上那个数字是错的** |
| **密钥不进仓库** | `.env` 被 gitignore;`.env.example` 进仓库。key 一旦进过 git 历史,删不干净,只能作废 |

## ★ 这门课最值钱的一条

**一个在自建测试集上 100% 的规则,可能只是"你记住了答案"。**

我给一条规则量出"3 真 0 假 = 100%",然后**造了一批没参与设计的题去撞它** ——
撞出来的是:**精确率确实没掉,但召回率只有 67%**。

**所以"我的系统准确率 X%"这句话,得先回答四个问题:**
1. **这个 X 是在什么条件下量的?**(自建集?没参与设计的集?)
2. **它测的是"对不对"还是"错得看不看得出来"?**
3. **换个数据,它还成立吗?**
4. **★ 量这个 X 的那把尺子,自己准不准?**
   —— 这一条是后来补的。见上面「我量过那把量分数的尺子」那一节:
   那把尺子当时会晃 ±1 道,而我先把它校准了才敢报数。

## 已知问题与边界

**诚实说明,不藏:**

- **来源分两种,不能混:**
  - **人翻 PDF 核** ✅ 现在所有数都能(如 `→ PDF 2025Q4 第9页`)
  - **程序追溯** ⚠ 只有**进了向量库的页**能。数据页(机场名单/分数表)从来没进库,
    所以那几个数**只能人翻,不能程序追**
- **2 个字的词搜不了**(trigram 索引要求 ≥3 字)。"删除""调整""口径"这类常用词全部落空
- **年度报告(2024年度)没进库**,文件名里没有季度编号,切片时被跳过
- **还剩 3 道题答不出**(#48 #51 #52)—— 但**每一道都会出声**,用户知道该换问法
- **一条规则有已知的洞**:只认「XX万级」,不认「XX万」—— 用户少说一个"级"字就漏
- **报告里的硬查有假阳性**:它会把「第 1 名」里的 1 报成"数据里没有的数"
- **不是有商业价值的产品**,是求职作品。技术实现保持入门级,不堆框架
