# 结论的条件 —— 哪些能直接讲,哪些要带条件

**为什么要有这份:** 张君杰改了一个数字(k=3 → k=5),那条"K>4 更差"的曲线**翻了面**。
顺着查下去发现:台账里躺着一堆结论,而其中一些是在【当时的系统状态】下量的。

> **不知道哪条已经过期,比不知道分数更危险 —— 因为你会拿它去面试。**

---

## 一、先把结论分成四类

```
甲  依赖【数据本身】   ——  不会过期。可以放心讲
乙  依赖【系统状态】   ——  会变。但那是"改好了",不是"结论错了"
丙  依赖【参数/机制】 ——  会翻面。必须带上条件
丁  【方法论】        ——  不依赖系统。是最硬的那一类
```

**★ 面试能直接用的 = 甲 + 丁。而 乙 要报"当前值 + 当前系统"。丙 要报"在什么条件下"。**

---

## 二、甲类:依赖数据本身(不会过期)

**这一类的共性是:它说的是【报告里有什么】,不是【我的系统怎么样】。**

| 结论 | 依据 | 现在 |
|---|---|---|
| **第 7 页有 3 个版本** | 抹掉期次名和空白后精确比对 | ✅ 稳(3 组) |
| 分界:2023Q3 / 2024Q1 / 2025Q1 | 同上 | ✅ |
| **库里 83% 是"同一页多期"的重复** | `GROUP BY 页码` | ✅ 稳(45/54 条) |
| 「行李服务」在 2023Q3~2024Q4,2025 起没有 | chunk 全文搜 | ✅ |
| 「靠桥率」在 2024Q1~2024Q4 | 同上 | ✅ |
| 2025Q1 起一级指标 6→7 项,去掉行李服务、加出港/进港 | meta 表 + 第7页原文 | ✅ |
| **数据页(机场名单/分数表)从来没进向量库** | chunk 表 vs PDF 页数 | ✅ |
| FTS5 默认分词器对中文**静默失效** | 实测:unicode61 搜"机场交通"命中 0 | ✅ |

**★ 这一栏的共同点:它们【不依赖我的代码怎么改】。换一个系统,这些事实还在。**

**★★ 所以这一栏是【面试最该讲的】—— 因为没人能反驳它。**

## 三、乙类:依赖系统状态(会变,但要报清"什么时候")

**★ 这一类的数是"进度",不是"结论"。报的时候必须带上系统状态。**

| 结论 | 当时 | 现在 |
|---|---|---|
| 准确率 | 61.9% | **60/60**(判分校准过之后量的)⚠ 见下面那段历史 |
| 去向对 | 52/60 | **60/60** |
| 静默失败 | 24 道 | **0 道** |
| 期次污染率 | 37% | **0%** |
| 告警率 / 误报率 | 0% / 0% | **100% / 0%** |
| 叙述·检索 平均 | 0.13 | **0.87** |
| 数值·比较 平均 | 0.58 | **1.00** |

### ★★ 关于那个满分 —— 它的历史比数字本身值钱

**同一个 60/60,前后出现过三次,而三次的意思【完全不一样】:**

```
① 2026-09-19 之前 —— 假的
   那个"答案"字段里装的不是回答,是【把取回的 5 页原文拼起来】:
       题52 的答案 1390 字 = P07 概况 + 4 张得分表 + "CAPSE于2012年成立"
   ★ 所以判分在那堆材料里找答案那句话 —— 当然找得到。
   ★★ 它测的是「材料里有没有那句话」,不是「系统会不会答」。

② 09-19(第 10 课)—— 加了生成层,分数【掉了】
   答案从 1390 字变成 12 字,而分数掉到 57、59。
   ★★ 而那才是真的 —— 掉的原因之一是:我自己的提示词写窄了
      ("一句话能说清就一句话" → 它把关键数字也砍了)。

③ 09-22(第 11~12 课)—— 60/60,而这次是【先把判分校准过】才量的
   ★★ 而且它连"答漏了一个并列第一"都能自己发现、自己补上,
      补的那句还标明了"这是代码算的"。
```

**★★★ 所以现在报这个数,必须连这句话一起报:**

> **"60/60 —— 但那是在【判分那把尺子被校准过】之后量的。
>   在那之前它是 59/60,而那个 59 比任何一个没校准过的 60 都可信。"**

**⚠ 说得不准的样子:**"我的系统静默失败 0 道"
**✅ 说得准的样子:**"在【期次过滤 + 多版本意识装好之后】的系统上,静默失败 0 道"

**★★ 而这一栏【最值钱的不是数,是那 24 → 0 的过程】** —— 因为那说明"静默"是可被消灭的。

## 四、丙类:依赖参数或机制(会翻面 —— 必须带条件)

**★ 这一栏最容易出事。它们看起来像"某个东西的性质",其实是"某个东西在某个系统上的表现"。**

| 结论 | 条件(它凭什么成立) | 现在还成立吗 |
|---|---|---|
| **「K>4 更差」** | 当时**没有去噪机制** → 多捞 = 多捞噪音 | ★★ **翻面了。** 现在 K≥5 略好于 2~4 |
| 「min→sum 排出来 2 道变、分数不变」 | 那两页的相对排序 | ✅ **没翻** |
| 「关掉改写问句掉 18.4 个点」 | 当时那些题的检索方式 | ⚠ 没重验 |
| 「max_tokens=80 没顶到」 | **那 60 道题的输出长度** | ✅ 稳(但换输入可能不成立) |
| 「硬限定词 3 真 0 假」 | 正式集那 5 道错题 | ⚠ 挑战集说召回率 67% |
| 「SQL 那条路一个检查都没有」 | 当时的代码 | ★ **过期了** —— 现在有 C 类检查了 |
| **「位置效应:两头的材料看得见,中间看不见」** | **旧提示词**(没有"每句标出处"那一条时) | ★★★ **作废了** —— 加了标出处之后,14 道题里 13 道完全不受位置影响。★ 而那条结论当初只在【1 道题】上量过,本来就该存疑 |
| **「给几页材料最好」** | 当前提示词 + 那 15 道检索题 | ⚠ **量出来是"分不清"** —— 给 5 页和给 2 页,9 道题一模一样。★ 而题48 给 2 页时 0/5,因为答案页排在第 3 位被砍掉了 |
| **「判分自己会晃 ±1 道」** | **旧判分提示词**(判据有三个洞没补) | ★ **修好了** —— 补洞 + 能算的交给代码之后,59/59/59 完全不晃 |

**★★ 这一栏的教训:**

> **一条测量结论,必须带上【它成立的条件】。**
> **条件一变,结论就作废 —— 而如果不写条件,没人知道它作废了。**

**★ 而 K 那次就是活例子:**
```
我写的是:  "K 有上界没最优,4 以上明显更差"
该写的是:  "在【没有去噪机制】的系统上(61.9%,错误集 16 道),K>4 更差。
             ⚠ 前提:多捞 = 多捞噪音。去噪机制装上之后,这个前提不成立 ——
                曲线在 96.7% 时翻面:K≥5 略好于 2~4,但差别骑在噪音上(±1.7)。"
```

## 五、丁类:方法论(最硬 —— 不依赖系统)

**★ 这一栏是从踩坑里长出来的,不是想出来的。而它们【换一个项目还成立】。**

| 规矩 | 它是从哪个坑里长出来的 |
|---|---|
| ★★★ **能算的地方,别问大模型** | **第 10 / 11 / 12 课,在三个位置各验过一次**:提问(表格解析)/ 判分(能算的交给代码就不晃了)/ 生成层(算出来补,不靠重试)。★ 而业界那条说得更硬:*"ground-truth validation produces much stronger correction than the model's own judgment"* |

| ★★ **先诊断,再动作** | 第 12 课:通用重试修不了特定故障。必须先认出是哪一类失败,再做【对应的】动作。★ 而这句话人在看代码之前先说了:"要想解决出错,首先我们得知道为什么出错的吧?" |

| ★ **"文本里找得到"不等于"答对了"** | 第 9 课:RRF 端到端 60/60 —— 后来查清,那不是"大模型全抄",是【代码把 5 页拼起来】当答案 |

| **一个数变好了,先问它测的是什么** | 第 7 课:告警率从 0 涨到 19%,而它测错了东西 |

**★★ 这一栏面试最能讲 —— 因为每一条背后都有一个具体的坑,而且都不是 AI 特有的。**

  —— 量出来是【分不清】:给 5 页和给 2 页,9 道题一模一样。
     所以那个旋钮【不值得调】,不是"还没调好"。

· 「判分的不稳定度 ±1 道」
  —— 只量了【两批答案、每批 3 次】。要给一个可靠的数,得跑更多次。

· 「60/60」
  —— ★★ 它意味着【这 60 道题已经用尽了】:
     改什么都不变,所以它现在只能当【回归测试】(改坏了没有),
     量不出进步了。要量进步,得出新题或者换尺子。

· 「内容忠不忠实」那一层 —— ★ 到现在【没有尺子】。
  试过一把字面的,修了四次,每次都把"格式差异"当成"内容差异"
  (页码漂 / 一个空格 / 改写 / 全角半角)。
  ★★ 最后发现:"照抄才算有据"这条判据,和"生成"这件事【天生冲突】,
      因为生成就是重组材料。
```

**★ 第 18 课新添的:**

```
· 「三版对照 6/6 一样」
  —— ★ 只跑了【一段 6 句的对话】。它证明的是"换形状没改行为",
     不是"三个执行器在所有情况下都一样"。

· 「LangGraph 装上了」
  —— ★★ 而它那三样能力(持久化/并行/中断)【一样都没用上】。
     所以现在说"用了 LangGraph"是【勉强的】——
     准确的说法是"我做了三版对照,主链选了零依赖那一版"。

· 「页面能跑」
  —— ★ 只在我这台机器上、用 Python 发请求验过。
     ⚠ 而两次失败是【测试工具的错】(curl 在 Windows 下发的中文不是 UTF-8),
       不是页面的错 —— 那种"工具错了、看起来像代码错了"最容易改错地方。

· 「State 是一个 TypedDict」
  —— ★ 那份字段清单是【我按现在这条路列出来的】。
     以后再分支,可能还要加字段 —— 而加的时候【没有东西提醒你】。

**★ 第 13~17 课新添的:**

```
· 「编造率 3/18 ≈ 17%」
  —— ★ 单次采样。而且它是在【已装上 5 道硬判据 + 循环】的系统上量的。
  ★★ 更要紧的:复现 8 次一次没抽到 —— 所以它是个概率，不是"每 6 次必有一次"。

· 「多版本提醒有效」
  —— ★ 只在【第 39 题】上量过(改前"混着说"、改后"分期说清")。
  ★★ 而且那次全量跑它掉到 0 分，我一度以为是我改坏的 —— 复现 8 次后发现
      8 次都写了那段，所以那次是【抽样】，不是改动造成的。

· 「60/60 回来了」
  —— ★ 第 13~17 课之间跑了很多次，59 和 60 都出现过。
  ★★ 那 1 分的差别是【第 39 题的判分本身在晃】(实测 9/10)，
      不是系统变好或变坏。

· 「Agent 那一层能接话」
  —— ★ 只在【5 句自检对话 + 4 个造出来的病例】上验过。
  ★★ 而它是【一个人设计的一句话】，不是真实用户的问法分布。

· 「Delete(取消记忆)」
  —— ★★ 到现在【没有真场景】。用户在这个系统里没说过"以后不用管合肥了"。
      所以 Delete 只有"清空"这个方法，没有验证过的路径。

· 「校验拦住了编的值」
  —— ★ 三个病例是【我造的】(monkeypatch 掉 llm.chat)，不是大模型真的编的。
      ★★ 真的大模型编的时候，形态可能不一样 —— 那几个病例只覆盖了
          "值不在库里"这一种编法。
```
