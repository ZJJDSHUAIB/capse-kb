## 一、背景

### 1.1 这个项目是什么

一个 **CAPSE 民航满意度知识库 + 报告生成系统**(`D:\capse-kb`),作品集性质,目标是飞常准(VariFlight)的 AI 应用实习生岗位。

系统做的事:把 54 页 CAPSE 报告切片入库,用户用自然语言提问 → 路由到「结构化查表」或「检索」→ 大模型基于检索到的那一页作答 → 代码回头查答案里的数字有没有出处。

**整个项目的核心命题只有一个:静默失败** —— 系统答错了,而用户读完整段答案都发现不了(格式正常、数字真实、答非所问)。

**当前状态**(在【期次过滤 + 多版本意识】装好之后):

| | |
|---|---|
| 端到端准确率(k=5) | 96.7%(58/60) |
| 去向对 | 60/60 |
| 静默失败 | 24 道 → **0 道** |

### 1.2 第 9 课在干什么

主题不是"学向量检索",是 **给系统加一个零件之前,先量它治的是什么病**。

- **第一节(已完成)**:装上向量检索(最小实现,只有编码模型是外来的)。在 14 道单页检索题上:关键词 12/14、向量 14/14。关键格子是「关键词对 · 向量错」= **0**。
- **第二节(本节)**:两条路各有各能对的地方,那怎么合?

### 1.3 ★ 本次要回答的问题,以及为什么原来的做法不够

`merge_variants.py` 里已有四条对照线,`merge_compare.py` 已在 60 道评估集上量过。

**然后张君杰提出了一个反对意见(原话):**

> **"怎么合是需要通过实验来验证的吗?那仅仅是针对这个评估集的哦,要考虑多种情况来测试才对吧"**

**这个反对意见是对的,而且是本项目第三次同类质疑:**

| # | 他的质疑 | 结果 |
|---|---|---|
| 1 | "补近义词是不是对这个测试集过拟合?" | 对。实测:带例子 3/3,换例子/不给例子/现状 **全部 0/3** |
| 2 | "用向量检索怎么就找不到?他们意思相近吧" | 对。我断言"向量治不了 #51 #52"是**没验过就说的**;装完一量,两道都命中 |
| 3 | "仅仅针对这个评估集吧" | **对。本文件就是在处理这一条** |

**为什么原来不够:**同一批题【既用来选、又用来判】,那个分数测的是"我有多了解这 60 道题"。而且那 60 道已全看过(读过、画过 K 曲线、重写过答案键),**标准的「留出法」已失效**。

→ 只能造**同一道题的新问法**:答案不变,只有问法变。

### 2.2 ★★ 三条挖出来的坑(它们本身就是发现)

**坑一:整句问句喂给关键词检索,命中 0 条。**

```
"2024Q2的著作权声明说了什么"   →   0 条
```

`search_multi()` 按**空格**拆词,每个词再走 trigram 短语匹配。整句中文没空格 → 被当成一个超长词 → trigram 要求这整串字在原文里挨着出现 → 0。

真系统从不这么干:大模型先把问句改写成**空格分开的检索词**。**所以变体表里「检索词」列才是实际生效的输入。**

**坑二(更值钱):给关键词喂近义词,机制上无效。**

题 51 系统实际用的检索词是 `2024Q2 著作权声明 版权声明` —— **近义词「版权声明」大模型自己已经加上了,照样找不到。**

查原文发现真相和"近义词"无关:

```
原文:  法律声明本数据统计分析报告的【著作权】归属航联传播……
检索词:著作权声明 / 版权声明
```

**「著作权」和「声明」在原文里都有,只是不挨着。** trigram 是短语匹配,要求这五个字连续出现。

→ **被破坏的不是"词的意思",是"字的位置"。**
(这也是质疑 #1「补近义词 prompt」的机制层解释:那次生效的根本不是检索这一步。)

**坑三:大模型推测的词,有些压根不在库里。**

`variant_expand.py` 按"在库里出现几次"给检索词排序,发现有几道题里出现次数**为 0** 的词:
`调整说明`(题38)、`新增指标`(题41)、`著作权声明`(题51)、`测评简介`(题52)。

→ 大模型改写时**造了库里没有的说法**。这在机制上必然失配。

**★ 而这里我还犯过一个标记错误**:期次词(如「2023Q3」)印在期次那一列、不在正文里,于是也被算成"出现 0 次",被标成"最独特的词"。**"库里一次都没有"和"很独特"是两回事** —— 和 `merge_compare.py` 里"把'不存在'说成'排得靠后'"是同一个病。已分开命名。

### 2.3 变体怎么来的:人工 16 行 + 机械 42 行

**★ 这个区分很重要,是本次的核心方法论。**

```
人工 = AI 用脑子设计的          4 道题 × 4 个变体 = 16 行
       ★ 设计者【知道答案】,所以挑的问法可能"刚好能被解决"

机械 = 脚本按死规则生成的        15 道题 × 3 条规则 = 42 行
       规则:① 拿掉期次词  ② 只留库里出现最少的词  ③ 只留出现最多的词
       ★ 规则写死,不看题目意思,谁跑都一样 —— 不带偏见
```

**为什么必须分开算:**"我知道答案去设计"和"规则写死"是两件可信度不同的事。分开算才能看出前者是不是有偏。

### 2.4 口径与条件

**全部由脚本自己吐出来钉在结果文件头上**,不是手写在一旁。

```
库 / 向量文件 / 变体表 / 各代码文件 的 md5 全部钉住
K              5(ask.py 实际生效的值)
期次过滤       开 —— 从【问法】里抽期次。变体拿掉期次词,过滤就随之关掉
喂给检索的是   ★「检索词」列,不是「问法」
判据           答案键那一页在【该方式实际给出去的条里】→ 算命中
               (★ 不按前 K 判:并集取前k 定义上不受 k 约束)
```

## 三、结果

### 3.1 主表(58 行)

| 组合 | 全部 | 人工(16) | 机械(42) | 剔除6行 |
|---|---|---|---|---|
| 只关键词 | 36/58 | 10 | 26 | 36/52 |
| 交集 | 36/58 | 10 | 26 | 36/52 |
| **向量单独** | 48/58 | **15** | 33 | 48/52 |
| 并集填位 | 48/58 | 13 | 35 | 48/52 |
| 1:1 两边一样重 | 50/58 | 15 | 35 | 50/52 |
| **2:1 / 3:1 更信关键词** | **51/58** | **16** | 35 | 51/52 |
| 1:2 / 1:3 更信向量 | 50/58 | 16 | 34 | 50/52 |
| 1:1 只看前5 | 50/58 | 16 | 34 | 50/52 |
| 1:1 只看前3 | 44/58 | 12 | 32 | 44/52 |
| 2:1 只看前5 | 48/58 | 13 | 35 | 48/52 |

### 3.2 ★★★ 发现一:权重几乎不敏感,真正的差别在"用一条路还是两条路"

```
用一条路:   只关键词 36      向量 48
用两条路:   50 ~ 51
```

**从 1:1 到 3:1 只差 1 格。而"一条路 → 两条路"差 12 格。**

**→ 所以"取交集还是并集、权重给多少"几乎不重要;【合不合】才重要。**

**★ 但注意:"合起来"只比"只用向量"好 2~3 格。而它带来的代价(多跑一遍检索、多一个可调旋钮、多一段代码)—— 一个都没量过。**

### 3.3 ★★★ 发现二:「关键词对 · 向量错」出现了 4 例,而且条件一致

第一节量出来是 **0**。本次在 58 行里找到 **4 例**:

```
45·去期次   45·机械·去期次   46·机械·去期次   49·机械·去期次
```

**★★ 四例【全部是"去期次"类】。** 机制(以题45为例,可复现):

```
检索词「CAPSE 创立 指标 系统」,不过滤期次
   关键词:  2025Q3-P11 排第 2   ✅
   向量  :  2025Q3-P11 排第 6   ❌

   关键词前5 = [2025Q2-P11, 2025Q3-P11, 2025Q4-P23, 2023Q3-P11, 2024Q1-P11]
   向量前5   = [2024Q4-P11, 2024Q2-P11, 2024Q3-P11, 2025Q4-P23, 2025Q1-P10]
```

CAPSE 简介这一页**每期都有**。一旦去掉期次过滤,同一页的 9 个期次版本就**互抢前 5 名**——而两条路抢法不同。

**→ 「关键词对 · 向量错」在【有期次过滤】时是 0,在【没有】时不是 0。**

### 3.4 ★★ 发现三:人工那 16 行【选不出旋钮】,机械那 42 行能

```
人工列:  2:1=16  3:1=16  1:2=16  1:3=16  只看前5=16   ← 五个并列满分
机械列:  2:1=35  3:1=35  1:2=34  1:3=34  只看前5=34   ← 差 1 格
```

**★ 区分度全在机械那批上。**

**★★ 我怀疑原因是:人工变体是【设计者知道答案之后】挑的,天然偏向"能被这套算法解决"的那几类。
机械变体的规则写死,没有这个偏向。**

**★ 而如果这个猜测成立,它比结论本身更值钱 —— 它说明"让 AI 设计变体"这件事本身就是偏差来源。**

**★★★ 但这是【推的】,没验。要验它,得让第二个人独立设计一批变体,看那批是不是也"选不出旋钮"。**

### 3.5 ★ 发现四:6 行"谁也没辙",剔除后不影响排序

```
42·机械·去期次        46·机械·只留最普通的词    48·机械·只留最普通的词
49·机械·只留最独特的词  50·机械·只留最独特的词    52·机械·只留库里没有的词
```

这 6 行**每一种组合都过不了** —— 不是规则的锅,是尺子的锅(检索词被破坏到谁也救不了)。

**★ 处理方式:留着 + 单列一栏。**理由和告警口径一样:**让一件事【可见】,和让它【影响结论】,是两回事。**

**★★ 量完发现:剔除它们【完全没改变排序】**(36→36、48→48、50→50、51→51)。
→ 它们只是平等地压低了所有分数,没有偏袒谁。**我的决定是个空操作 —— 但那本身有用:证明这 6 行是中性的。**

### 3.6 ★ 发现五:检索成不成,取决于目标页**有没有别的页没有的词**

```
题48:目标页有「1000万-1500万」全库独一份  →  人工 4/4,连去掉档位词都命中  (容错)
题52:目标页是「CAPSE简介」每期都有       →  人工 1/4,只有去期次那行靠运气赢 (脆)
```

**★ 而"脆"的那些正是静默失败高发区** —— 测试时恰好命中,上线换个问法就悄悄错了。

## 四、结论

### 4.1 可以说的

1. **在正常问法上,权重这个旋钮【选不出来】。** 1:1 到 3:1 只差 1 格,人工那 16 行甚至五个值并列满分。

2. **能选出来的是另一件事:用一条路 vs 用两条路,差 12 格。** 所以"要不要合"比"怎么合"重要得多。

3. **「关键词对 · 向量错」出现 4 例,条件全部是"没有期次过滤"。** 机制是同一页的多个期次版本互抢,两条路抢法不同。

4. **"合"只比"只用向量"好 2~3 格。**而它带来的代价(多跑一遍、多一个旋钮、多一段代码)**一个都没量过**。

5. **给关键词喂近义词机制上无效;大模型推测的词有些压根不在库里**(坑二、坑三)。这两条是硬的 —— 来自代码实现和 `LIKE` 计数,不是统计。

6. **6 行"谁也没辙",剔除后不影响排序** —— 它们是中性的。

### 4.2 ★ 不能说的

1. **这不是一个实验结论。** 58 行、15 道题,**全部由 AI 设计或 AI 定的机械规则**。"选哪些变体"本身就是一种判断,而我没有第二个人来对冲它。

2. **不能说"2:1 更好"。** 只差 1 格,而且那差别全在机械那批同质变体上。

3. **不能说"合一定比不合好"。** 2~3 格,而且代价没量。

4. **不能说"人工变体太友好"** —— 那是推的,没验(见 3.4)。

5. **不能说"期次过滤有害"。** 58 行里它有好有坏,而在 60 道评估集上它的端到端效果是正的。

6. **`my_merge.py` 的 1.0/1.0 是【中性默认值】,不是最优值。**已在代码里显式标注。
