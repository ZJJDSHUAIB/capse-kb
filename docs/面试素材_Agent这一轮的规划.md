# 面试素材：我怎么把一个「会答错」的问答系统，改成「答错时看得出来」的

> ★ 这一份是【能直接讲的】。每条都带【具体的数】，而每个数都是跑出来的。
> ⚠ 它补的是第 7 课那份 —— 那份停在第 12 课，这里面的东西不在里面。

---

## 一句话

> **我做的不是"让它答得更准"，是让它【答不出来的时候说出来】——
> 因为答错而用户看不出来，比答不出更坏。**

---

## 那这个项目是什么

一个**机场服务满意度问答系统**（数据来自 CAPSE 的公开报告，9 个季度、44 家机场）。
用户用大白话问，系统去库里查，答出来并给出处。

**★★ 而它一路在打的一个东西：静默失败 —— 系统答错了，而用户读完整个答案都察觉不到。**

```
格式正常 · 数字真实 · 出处齐全 —— 而答的不是他问的。
```

---

## 我这一轮做的四件事

### 一、机场简称：1/22 → 22/23

```
现象:用户问「浦东2025Q4…」，系统说"没找到这个机场"。
量:  拿 30 个"人真正会说的叫法"去量 → 该答的 22 个，只认出 1 个。
根因:匹配方向反了 —— 代码问的是「库里的名字是不是问句的子串」，
     而「上海浦东」不是「浦东」的子串。★ 而人说的就是「浦东」。
修法:方向反过来 + 按期的唯一性检查。★ 没为任何一种说法写规则。
     都是从库里算的（子串 + 期次 + 唯一性），一个模型都没用。
结果:22/23，而且【3 句下游的题自己变好了】—— 我没为它们写一个字。
```

**★★ 而那 3 句自己变好，才是这件事值钱的地方：**

```
「浦东2025Q4比同一档的平均高多少」      原来拒答 → 答对
「浦东2025Q4所在的档位，大家平均考多少分」原来答了个别的 → 答对
「浦东2025Q4跟同档的均值差多少」        原来拒答 → 答对
```

**★ 我管这叫「接线」而不是「补丁」：接完线，有几句话自己变好，而规则一条没加。**

### 二、同档平均：0/5 → 5/6，还补了一段

```
现象:问「浦东和同档平均比怎么样」→ 答了"浦东 4.23，排名 5/42"（答非所问）
量:  拿五种问法去问同一个量 → 【0 种答对】，其中 2 种是静默的
根因:那个数【库里有】，而没有一条路通向它。
修法:接一条路。
```

**★★★ 而后来用户一句话推翻了我自己标的东西：**

```
我标的:  「和同档平均比怎么样」= 一个数
         「算是什么水平」      = 库里没有这条路
用户说:  这两句【没区别】，而且我要的是【先给数、再给一张表】
真相:    ★ 同一句话少了一整段 —— 系统只会给【数】，【表】那一段根本没有。
        前一句看起来"答上了"（给了数），后一句看起来"答不了"（一段都给不了）——
        其实是【同一个毛病】。
```

### 三、「答了没有」这件事，修成看得见

```
现象:多轮里问「那在它那一档里算是什么水平」——
     返回里写着 "结局": "答"，而答案是【空的】。
根因:「结局」只看【走没走到那个动作】，不看【那个动作成没成】。
     ★ 而"走到就算成了"这句话，在 4 个地方各写了一遍。
★★ 而判断【本来就有】—— 它写在终端那个展示文件里。
   于是:终端看得见 · Web 看不见 · 评估看不见 · 图版看不见。
   ★ 把判断写在一个【消费者】里，而不是产生结果的地方 ——
     改的不是半个功能，是【半个世界】。
结果:4 处硬写 → 1 处判断，四处都读它。
★★★ 而它一照出来，露出【两个被藏住的 bug】（借了期次不置标记 / 认不出 vs 确定没点名）。
     一个失败的操作报出成功的消息 —— 它藏住的不止一个失败。
```

### 四、省略句：补了实体，还要补问法

```
现象:问「那虹桥呢」—— 实体借对了、期次借对了，而答案【比上一轮少一层】。
根因:上一轮那句话里写着【要问什么】，而这一句里【什么都没有】。
     ★ 省略句补全，补了【实体】，没补【问法】。
修法:判据是【这一轮的句子，自己对得上库里的量名吗?】
     「那虹桥呢」            → 对不上 → 没说问什么 → 借上一轮的问法
     「那 2024Q2 的得分呢」   → 命中「得分」→ 说了 → 不借
★ 而这个判据是【能算的】（量名从表结构来），不是靠模型选没选。
结果:两个方向都对 —— 该借的借了，不该借的没借。
```

## ★★★★ 四个能直接讲的判断

### 判断一：能算的算，算不出的才问

```
机场名这一侧  用户说的字 ⊂ 库里的名字（浦东 ⊂ 上海浦东国际机场）
              → 子串 + 期次 + 唯一性就够了，全 SQL
量名这一侧    「均值」「同档水平」和任何字段名【一个字都不共用】
              → 必须语义
★ 所以不是"把词表换成向量"，是【两半各用各的办法】。
```

### 判断二：出口比识别重要

```
我一开始以为毛病是"词表太短"→ 换成向量就行。
量下来不是:真值有四态（是 / 含糊 / 缺路 / 否），而现有判据只有两态。
★★ 所以靶子变了:不是"认得出更多说法"，是【该说含糊的时候说含糊】。

而四种实现跑同一批句子:
   A 现有那个两态正则   10/14   ← ★ 最好的，就是它原来那个最笨的
   C 改写              8/14
   D 字面优先 + 兜底     7/14
   B 向量              6/14
★★★ 加出口的那几个，出口【全变成了逃逸口】:
     一句提示词写「那两个不算错」，7 句全被推给了出口，从 9/14 掉到 7/14。
```

### 判断三：框架管「状态不丢」，不管「状态被用上」

```
同一个 bug，三个实现跑同一个两轮对话:
   手写 if 版 / 我写的 40 行图版 / LangGraph 版 ——
   【结局、参数、说明全都一模一样】，连说明那一栏都一样。
   ★ 而 LangGraph 版【用了持久化】。

→ 它保证的是【状态存下来、带过来】—— ★ 它做到了（期次确实带着来了）
→ 而 bug 在【带过来之后怎么用】—— 那段代码三版共用，框架管不到那儿
★★ 一句话:「用了框架」不等于「框架会替你想清楚业务逻辑」。
```

### 判断四：判断要写在产生结果的地方

```
见上面第三条 —— 判断写在【一个消费者】里，是"半个世界"的问题。
```

## ★★★★★ 我踩的坑（而它们比结论更值钱）

```
① 我推的方案，被量出来的数【否掉了四次】:
      B 向量 8/14  ·  D 字面优先 7/14  ·
      给出口反而更差 9→7  ·  "模型选了干活类"这条判据判错了
   ★ 四次我都以为"换个更好的实现就行"。

② 量具【自己坏了七次】，而且坏法都一样:
      反引号没去 → 正向算成 0 句，报出一个"看着像样"的数
      没写期次   → 尺子声称覆盖 14 句，实际只覆盖 6 句
      真值没归一化 → 报"系统错了"，其实是尺子错
      ...
   ★★ 而被测物只有一套，尺子要"想清楚被测物该干什么"—— 那一层最容易错。

③ 出题人=判卷人 —— 而它翻车过两次:
      我自己标的真值，被用户推翻两次（"没区别" / "上海该反问"）
   ★★★ 所以：真值必须来自别人，或者来自库（能算的那种）。
```

## ★ 如果只能用一句话

> **我四次以为"换个更好的实现就行"，四次被量出来的数打回来 ——
> 而最后站住的那个，是它原来那个最笨的两态正则，加一个出口。**

**★ 而支撑这句话的方法只有一条：先立尺子，再动代码；而尺子自己也要被量。**
