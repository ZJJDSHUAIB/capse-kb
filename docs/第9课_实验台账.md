## 一、第一节:两种检索各自漏什么(已跑完)

在**同一批 14 道单页检索题、同一个 k=5** 下:

```
关键词命中   12/14
向量命中     14/14
关键词对·向量错    0     ← ★ 这一格是 0:向量没有错过任何一道关键词对的题
关键词错·向量对    2     (#51 #52)
两个都错            0
```

**★ 由这一格 0 直接推出来的两件事(不用再跑):**

```
并集 = 14/14  = 只用向量
交集 = 12/14  = 只用关键词
```

**所以"并集还是交集"在这批题上根本没得选** —— 它俩各自等于"只用其中一种"。
而且这两个数**必然**是那样,是集合运算的性质,**不是实验结果,没有信息量**。

→ 真正的问题只剩一个:**k 不变的时候,谁在前 k 名。**
   而并集想不变大就必须排序;两种分数(BM25 负值 / 余弦 0~1)又不可比 → 只能按**名次**排。

**判分看不出来这个代价,因为判分只问"答案在不在文本里"。**

## 二、怎么量 —— 张君杰定的口径

> **"有大模型参与的话,允许回答有一定小范围的波动;如果由程序回答的话那就必须分毫不差。"**

**★ 这条口径自己就是一把校准工具:**

```

   SQL 37 道 + 拒答 8 道 = 45 道
★ 拿它去量天平(判分)→ 天平晃多少,就是判分自己的噪声
```

**⚠ 一个必须先处理的技术坑:**

```
score_eval 有判分缓存,键 = (题号, 期望答案, 系统答)。
★ 而"量判分稳不稳"要拿【同一份答案】反复判 → 键完全一样 → 100% 命中缓存
★★ 那读到的"稳定"是【缓存命中】,不是判分给的。
→ 所以加了 --no-cache(而且开着它时【也不写缓存】,免得污染)
```

## 三、第一次量:答案不动,只重判

```

   第1次 [46, 48]      第2次 [46, 47, 48]      第3次 [40, 46, 48]

★ 46/48 三次都判错(它们确实错)      ← 稳
★★ 47 只出现 1/3 次                ← ★ 在晃
★★★ 40 只出现 1/3 次              ← ★ 在晃
```

**→ 判分【确实会晃】。而这次实验答案没重跑,所以晃的只能是判分。**

## 四、晃的原因:判据有三个洞

**★ 判分收到的指令:**

```
     (全是满分,尺子再晃也看不出来)。
     ★★ 真正量出判分晃的,是第二批【边界答案】—— 58/57/57,题47 判对 4/10。

⚠ ③ 他没意识到:那次数据【正好验证了他自己定的口径】——
     程序控制的 45 道波动 0,大模型生成的 15 道确实在晃。
     ★★ 也就是"没有量到噪音"这句话是错的:噪音量到了,而且精确落在他划的那条线上。

⚠ ④ 第三题(为什么 60 降到 59 是好事)—— 【没答】
```

**★★ 所以这两课的复述,只过了一半。上面四条标 ⚠ 的,下次接着讲。**

# 第 12 课 · 先查别人怎么做(2026-09-22)

> **起因:张君杰问了一句 ——**
> **"我们的修法确实有效,但仅仅是针对这个试题的。别人的循环也是这样修的吗?
>   还是说有一些通用的办法呢?我觉得我们的眼光可以放的广一些,以后都是。"**

**★ 我当时的反应是:这个问题该【联网查】,不该凭印象答。所以查了。**

## 一、业界最关键的一条:**通用重试修不了特定故障**

> **"Retrying can help a transient timeout, but it does not repair stale retrieval context."**
> **"recovery should be conditioned on the observed failure signal, inferred failure
>   class, current execution state, and remaining recovery budget."**

**★★ 翻译:恢复方式必须【匹配故障类型】。业界把这叫做
「diagnose-then-reformulate over blind retry」—— 先诊断,再改写,别盲目重试。**

**★★★ 而张君杰在看到一个字的代码之前,先说了同一句话:**

> **"要想解决出错,首先我们得知道为什么出错的吧?"**

## 二、业界给的"什么时候该改写查询"的信号

```
· 结果全来自同一处         (太窄)
★ 字面重合高但语义不匹配    (术语不对)
★ 期次不对                (加时间过滤)
· 语言不对
```

**★★ 四条里,两条我们【已经有真例】:**

```
· "结果全来自同一处" → 第 9 课:「第 7 页占了 5 个名额,把真答案页挤掉」
★ "术语不对"       → 题51:「著作权声明」vs 原文写的「法律声明」
```

## 三、★★★★★ 有一条,业界和我们说的是同一件事

> **"Grounding the feedback signal in ground-truth validation (e.g., running code
>   and returning real results) produces much stronger correction than the model's
>   own judgment, and guards against sycophantic 'agreeing away' of mistakes."**

**★ 翻译:反馈信号锚在【真值校验】上,纠正效果【比模型自己的判断强得多】。**

**★★ 而我们这一路那句话是:"能算的别问大模型"。**

**★★★ 同一个意思 —— 而我们是【从踩坑里长出来的】,不是抄来的。**

## 四、循环上限:业界给的是「2~3 次」,而且是量出来的

```
· 有份 ADR 明确写 max_retries = 2(共 3 次尝试)
  ★ 理由:第二次带着【校验给的明确错误反馈】,通常就能成功
  ★★ 无限重试被否掉,因为:
     "the signal of genuine failure disappears under retry-loop noise"

· 另一个生产例子(Claude Code 的上下文压缩熔断)用【连续 3 次失败】当阈值,
  ★ 依据是真实会话统计里的拐点
```

**★★★ 而"信号被噪声盖住"这句,我们第 11 课【亲自量过】——
判分自己就在晃 ±1,而循环会让它更难看清。**

## 五、对照表:我们缺哪几块

| | 通用做法 | 我们 |
|---|---|---|
| 判据锚在哪 | 锚在真值校验,不靠模型自评 | ✅ 一样(四道硬检查) |
| 重试前干什么 | ★ 先诊断故障类型,再决定怎么改 | ⚠ 还没做 |
| 循环上限 | ★ 2~3 次,量出来的 | ❌ 还没定 |
| 失败分类→对策 | ★ 每类失败对应不同的恢复动作 | ⚠ 刚分清两类 |
| 成本控制 | ★ 设成本比阈值,超了就停 | ❌ 还没做 |

**★★ 结论:大方向对,细则缺几块。而缺的那几块,恰好就是"通用循环"该有的样子。**

## 第 12 课 · 最小循环(2026-09-22)

### 一、它是什么

```
生成 → 诊断(哪一类失败) → 做【对应的】动作 → 再看结果
```

**★ 和"盲目重试"的区别(业界那条):retrying does not repair stale retrieval context ——
通用重试修不了特定故障。所以【先诊断,再动作】。**

**★★ 而这一条,张君杰在看代码之前先说了同一句话:**

> **"要想解决出错,首先我们得知道为什么出错的吧?"**

### 二、循环【设计成能容纳两种动作形态】

```
「再来一轮」型 —— 换个输入,再生成一次
   用于"说不清哪一步出的问题、只能再赌一次"的情况
   ★ 它靠赌,所以有上限(MAX_RETRY = 3,照抄业界的 2~3)

「一次到位」型 —— 算出来补上
   用于"失败原因清楚、而且能算"的情况
   ★★ 它【不赌】—— 算出来就确定,补完就结束,不进下一轮
```

### 三、⚠⚠ 而截至今天,【在用的只有「一次到位」一种】

**「再来一轮」写出来过,后来实测发现依据作废、而且有风险,删了。**

```
它原来的动作是"少给材料,再生成一次"。依据是第 10 课那个实验:
   给 1 页 答对 100%  /  给 5 页 答对 20%
 → 看起来是"材料太多,它看漏了"

★ 但那个实验是在【旧提示词】下做的。加了"每句标出处"之后,
  位置效应没了 —— 那个依据【已经作废】。

★★ 拿当前提示词重新量(检索题,给 5 页 vs 给 2 页,各 5 次):
      9 道题:两边一模一样,没差别
      题48:给 5 页 5/5,给 2 页 0/5
      ★★★ 而那个 0/5 不是"少给更好",是【答案页被砍掉了】——
           它的材料里答案页排在【第 3 位】。

★★★★ 所以:依据作废 + 本身有风险(会砍掉答案页)→ 删。
```

**★ 但【诊断留着】—— 因为那类失败真的会发生(题45 发生过)。
诊断出来而没有对策时,trace 里会写下是哪一类,然后停。**
**——「判不出看得见」:至少它出声了。**
