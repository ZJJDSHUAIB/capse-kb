# 这个项目的脉络

**给要讲它的人看。** 不是罗列做了什么,是串出**为什么这一步必须在下一步之前**。

---

## 一句话

> **把 9 份 PDF 报告,变成一个能回答问题、能出报告、而且【知道自己哪里不可信】的系统。**

**而贯穿全程的,只有一个主题:静默。**

---

## 一、主题:什么最贵?

```
答错了一个数        →  用户可能追问,能纠正
答错了一个数,而且    →  用户拿去用了,而且不会怀疑
用户看不出来
```

**第二种叫「静默失败」。** 它有三个特征:

```
① 格式正常   ——  有出处、有条理,看上去是个正经答案
② 数字真实   ——  它没编,那些数真的在库里
③ 答非所问   ——  但它答的不是你问的那个问题
```

**这个项目从头到尾打的,就是它。**

**而它最典型的形态,是"看起来对,实际不对"的机制** ——
一个缓存文件在长、在被写,但从没命中过;一个显示用的截断,变成了判分依据;
一个 100% 的规则,其实只是"记住了答案"。

**每一次都不是"坏了",是"看不出坏"。**

---

## 二、链子的五站(第 1~5 课)

**一句问话变成答案,中间有 5 站。每一站都可能出错。**

```
① 切片      PDF → 库里的"块"
             │  为什么:PDF 不能直接查
             │  踩过的坑:一页 ≠ 一块(数据页/空白页被丢掉)
             ↓
② 建库      块 → 带约束的 SQLite
             │  为什么:"按页切"之后要能约束"什么数据不该进库"
             │  原则:约束写在库里,不写在人心里
             ↓
③ 索引      库 → 能搜到
             │  为什么:库里的文字要能被检索
             │  踩过的坑:中文必须 trigram —— 默认分词器【静默返回 0,不报错】
             ↓
④ 路由      问句 → 该走哪条路(SQL / 检索 / 拒答)
             │  为什么:不是所有问题都用同一种方式答
             │  原则:判不出看得见,判错看不见 → 所以"拿不准"要单独一档
             ↓
⑤ 组装      查到的 → 一个能负责的答案
             │  为什么:搜到了还要能负责地给出去
             │  规则(你定的):① 必须带来源 ② 跨口径必须说明
             ↓
          ✅ 系统能跑了
```

**★ 到这里,它能回答问题 —— 但你不知道它答得有多差。**

**★★ 而这 5 站里,"静默"已经出现过三次:**

```
第 3 课  查不了 ≠ 查了没有          (2 字的词搜不了,它返回空,不说"我搜不了")
第 4 课  判不出看得见,判错看不见    (这条被提炼成了原则)
第 5 课  0 条检索 ≠ 拒答            (两种不同的失败,共用一个去向)
```

## 三、造一把尺子(第 6 课)

**问:怎么知道它多差?**

**答:造 60 道题,自己写标准答案。**

**★ 而这里有个陷阱,你当时就问出来了:「我人工有失误怎么办?」**

**→ 所以有了两个脚本,分工要分清:**

```
check_eval.py   核【评估集自己】  —— 你写的标准答案,去库里对不对得上
score_eval.py   核【系统】        —— 拿评估集去问系统,系统答得对不对
```

**⚠ 而 `check_eval.py` 有个说清的边界:它和库是同一条路,一起错了看不出来。
真独立的核对只有一条路:人回去翻 PDF。**

### 量出来的东西

```
准确率 61.9%      60 道错 24 道

★ 而 24 道错,【警告字段全是空】—— 全部静默。
```

**这就是这个项目最重要的一次测量:系统的失败,它自己一点都不知道。**

### 你的三条评估口径(这一课你的产出)

```
① 叙述题:证据命中(硬判) 且 意思对(大模型判)—— 两个都要过
② 复合题:拆子项,部分得分 —— 分数是 [0,1] 连续值,不是 0/1
③ 0 条检索 ≠ 拒答 —— 三者互不相等:检索 / 检索·0条 / 拒答
```

**★ 第 ③ 条立刻逼出两个真 bug:**
**一个规则只装在一条路上(年度报告那条),一个失败没有自己的去向。**

## 四、改它,而且证明改动是真的(第 7 课)

**这一课的问题不是"怎么改",是【怎么知道改对了】。**

### 而这里踩了三个大坑

**坑 ①:尺子自己坏了**

```
判分代码:score = 答对的子项 ÷ 所有子项
而循环会【跳过没有数字的子项】—— 那些项永远拿不到分,却永远占着分母

→ 8 道题的满分被压成 2/3,【永远到不了 1.0】
→ 而它们一直答对了。
```

**坑 ②:一个缓存从来没生效过**

```
缓存键用了 Python 内置的 hash() —— 它对字符串【每个进程加随机盐】
→ 键每轮都变 → 缓存一次都没命中 → 每轮重判 → 判分噪音 ±1.7 个点

★ 而它文件在、在被写、长度在长 ——【看起来完全正常】
修完之后加了一条:让缓存自己报命中率。静默的机制要让它出声。
```

**坑 ③:一个数变好了,先问它测的是什么**

```
我做了个检查,让"错误告警率"从 0 涨到 19% —— 看着像成功了。
查下去发现:它测的是【用户用的词在命中的页里有没有】,
而它"报对了"的那几道,是【巧合】。

★ 答案可以带出处、格式漂亮、数字是真的,而答的是另一个问题。
  指标也可以带着改善、方向正确、动了两位数字,而测的是另一件事。
```

### 而这一课的方法,是这么长出来的

```
· 一次只改一个变量
· 每次跑两遍,不一致不算数
· 先押预期,再看实际 ——【押错比分数难看更有信息量】
· 改坏实验:故意把参数改坏,看掉多少
    掉得多 → 这个旋钮是接上线的;  掉不动 → 它是死的
· 一次只动一处,立刻落盘
```

**★ 还有一条,是你自己提出来的:**

> **「这是硬编码吗?就不能像人一样理解文本然后回答吗?」**

**→ 答案不是二选一,是【分工】:**

```
代码管   「说什么数」        ← 硬,可核
大模型管 「怎么把数说成话」   ← 软,但它只能用手里的数
    再管 「下什么结论」       ← 软,而且【标明是推断】
代码再查 「数有没有出处」     ← 硬,把关
```

**硬的地方管"有没有"和"对不对";软的地方管"怎么说"。**

## 五、最后的形态(第 8 课)

**从"一问一答"到"一份能拿出去的报告"。**

**而报告会放大两件事:**

```
放大【错误的绝对数量】   30 个数字 × 8% 错 → 大概 2~3 个错
放大【错误的影响力】     问答里用户会追问;报告里数字直接变成结论
```

**所以报告的门槛不是 91.7%,是:「一份报告里,有多少数字是【错的、而且没标出来的】」。**

### ★★ 而这一课挖出了一个【根】

**你问:「程序为什么不知道有多页?那以后遇到类似问题不都回答不了了吗?」**

**查出来的答案:**

```
chunk 表【有】页码列 —— 程序知道哪几条页码相同。
但它从来没有拿这个信息做过任何事。
检索时,每条 chunk 是一个【独立的候选】,它不知道"你俩说的是同一页"。

而库里有【83%】是这个形状。
```

**★★ 这一课【所有】检索类失败,根都在这里:**

```
#39  多版本不可见   →  只取到 9 条里的 1 条
#42  跨期矛盾       →  取到两期的同一页拼在一起
#48/#51/#52 取错页  →  P07 有 9 条,每条都在竞争,★ 一页就占了 3 个名额
期次污染 37%        →  同一个根
```

**★ 五个症状,一个根。而前面每一轮都是【按症状在治】。**

**修完之后:**准确率 93.3% → **95.0%**,静默失败 **24 道 → 0 道**。

## 六、第 9 课:两条路怎么合 —— 而实际学到的是「换个条件再量」

**从"一种检索"到"两种检索,合起来用"。**

**但这一课真正学到的东西,不是"怎么合",是:一个数,你得先问它凭什么成立。**

```
第一节量出来:关键词命中 12/14,向量命中 14/14
   → 看起来结论很清楚:"用向量"
   ★★ 而那一刻有人问了一句:"那仅仅是针对这个评估集吧?"

于是换 58 种问法重新量 —— 结论就变了:
   一条路 36~48 道,两条路合起来 50~51 道
   ★ 而"怎么合"(并集/交集/按名次)几乎不影响,只差 1 道
```

**★★ 所以这一课的结论是一句反过来的话:要不要合,重要;怎么合,不重要。**

**★ 而过程中挖出一个更硬的事实:**

```
库里有 83% 是"同一页在多期"的重复 ——
★ 同一份内容,各期的文本【只差 2~8 个字】(通常就是期次名本身)。

→ 所以"期次"这个信息,在正文里【几乎不存在】。
→ 而"这一页属于哪一期"这件事,【大模型也分不出来】。
```

**★ 判断(这一课人做的):「先怀疑,再去量,别把一道题的现象当成规律」**
—— 那一课"位置效应"被立起来过,又换 14 道题推翻(13 道不敏感)。

## 七、第 10 课:系统根本不会回答 —— 它只会搬书

**从"把资料堆给用户"到"真的回答一句"。**

**★ 这一课开头是查一个满分是怎么来的,查出来的是:**

```python
# 那一行代码
out["答案"] = list(page_notes) + [h["文本"] for h in hits]
```

```
用户问:"CAPSE 是哪一年成立的?"
系统答:1390 字
   开头 "CAPSE机场服务测评包括综合得分1项…"    ← 另一页
   中间 4 个档位的机场得分表                    ← 无关
   末尾 "CAPSE于2012年正式成立"                 ← 答案在这
★ 而判分给了满分 —— 因为那句话在里面。
```

**★★ 所以那个 60/60 测的是【资料里有没有那句话】,不是【系统会不会答】。**

**加了生成层之后(1390 字 → 12 字),分数掉到 57,原因居然是**
**我自己的提示词写窄了("一句话能说清就一句话"→ 它把数字也砍了)。改掉就好。**

**★ 而这一课最后落成四道【硬检查】,全是代码,没有一道让大模型判自己:**

```
audit_answer         回答里的数字,材料里有吗
check_citations      回答标的出处,真在材料里吗
check_missed         它说"没有",而检索词其实搜得到吗
check_ranked_answer  分档排名答全了吗(★ 从表里算出来的)
```

**★ 判断(这一课人做的):「只允许回答精准,有无关内容都算错」**
—— 那是判据,不是分数。它逼出了上面那四道检查。

## 八、★★ 第 11 课:量那把「量分数的尺子」

> **★ 这一站是整条线的顶点。面试讲的就是它。**

**从"量系统"到"量那把量系统的尺子"。**

**★ 起因是这一句(人定的口径):**

> **"有大模型参与的话,允许回答有一定小范围的波动;
>   如果由程序回答的话,那就必须分毫不差。"**

**★★ 而这句话【自己就是一把校准工具】:**

```
纯程序那部分(答案确定)= 已知重量的砝码
   SQL 37 道 + 拒答 8 道 = 45 道
★ 拿它去量天平(判分)→ 天平晃多少,就是判分自己的噪声
```

**★★★ 量出来的结果:**

```
拿同一批答案判三次:  58 / 57 / 57
   第1次 判错 [46, 48]   第2次 [46, 47, 48]   第3次 [40, 46, 48]
★ 同一批答案,三次判出来的错题不一样。

查下去,原因不在模型,在【判据有三个洞】:
   · "关键事实一致就算一致"  —— 名字对、数字没给,算不算?没写
   · "数字"两字明明在那儿     —— 少一个数字算不算?没写
   · "多说了别的,不算错"     —— ★ 那【少说了】呢?没写

补洞(补过头会误伤,试了两次)→ 58/57/57 → 59/59/60 → ★ 59/59/59 不晃了
```

**★★★★ 而这一课真正的收获是一句话:**

```
★ 校准之后,分数【掉过】一次:60 → 59。
★★ 而那一次掉分是好事 —— 因为掉的那一分是假的。

   60/60 里有一道"悄悄漏了并列第一",而判分看不出来;
   59/60 里那一道被【稳定地判出来了】,而且理由是从表里算出来的。
```

**★★ 判断(这一课人做的):上面那句"程序的分毫不差,大模型的允许波动"**
—— 一个口径,同时变成了判据和校准工具。

## 九、第 12 课:最小循环 —— 而它验出一个该删的动作

**从"生成一次"到"生成 → 诊断 → 做对应的动作"。**

**★ 起因是一句话(人问的):**

> **"我们的修法确实有效,但仅仅是针对这个试题的。别人的循环也是这样修的吗?"**

**★★ 查了(所以那一课有一节是网上来的)。业界最关键的一条:**

> *"Retrying can help a transient timeout, but it does not repair stale retrieval context."*
> *"diagnose-then-reformulate over blind retry"*

**→ 通用重试修不了特定故障。必须先诊断是哪一类,再做【对应的】动作。**

**★★★ 而那一条,人在看代码之前先说了同一句话:**

> **"要想解决出错,首先我们得知道为什么出错的吧?"**

**★ 做出来的循环:**

```
生成 → 诊断(哪一类失败) → 做对应的动作 → 再看结果

而动作【设计成能容纳两种形态】:
   「再来一轮」型 —— 换个输入再生成(靠赌,有上限)
   「一次到位」型 —— 算出来补上(★ 不赌,因为算出来就确定)

★ 而实测之后,只留下「一次到位」那一种:
   另一种的依据(材料太多看漏)是【旧提示词下的现象】,已经作废;
   重新量还发现它【有风险】—— 会把答案页砍掉(题48 给 2 页时 0/5)。
```

**★★ 判断(这一课人做的):「先诊断,再动作」**
—— 而那也正是"能算的地方别问大模型"在【生成层】的又一次验证
(前两课在【提问】和【判分】上验过)。

## 十、贯穿全程的几条原则

```
① 判不出看得见,判错看不见
      → 所以宁可让它说"我不知道",不可硬答一个

② 同一个字段有两个身份,迟早出事
      → 显示用的文本 和 判分用的文本,不能是同一个变量
      → "答案" 和 "摘要" 必须分开

③ 静默的机制要让它报数
      → 缓存要报命中率;截断要看得见;规则要能被打出来

④ 量具只覆盖它覆盖的地方
      → "没撞到"不等于"没有"
      → 先问一句:我的量具够得着它吗?

⑤ 修 bug 优先于加功能
      → 这一课最大的一次收益来自修尺子,不是加机制

⑥ 一个数变好了,先问它测的是什么
      → 恶化看得见,改善才需要怀疑

⑦ 别拿旧分类判断新问题
      → 分类是线索,不是结论;它随错误集变化要重做

⑧ 从上游往下游改
      → 上游一变,下游调好的参数就作废

⑨ 格式该迁就人,只要不产生歧义
      → 而产生歧义的格式,比缺信息更危险
```

## 十一、你面试可以怎么讲(15 分钟版)

**开场一句话:**

> 我做了一个机场满意度知识库:9 份 PDF、一个 SQLite、一套自建评估集。
> **但我想讲的不是"它答得多准",是【我怎么知道它准】——**
> **而且更进一步:★ 我怎么知道【那把量准不准的尺子】,自己准不准。**

**★★ 这句话是全场的轴。前三个故事讲"造尺子",第四个讲"校准尺子"。**

**然后讲四个故事(每个 3 分钟):**

**故事一:24 道错,警告全是空**

> 我造了 60 道题量它,准确率 61.9%,错了 24 道。
> **而这 24 道,它自己报的警告【全是空】** —— 它不知道自己错了。
> 从那天起,我的目标就从"少犯错"变成了"犯错时知道"。

**故事二:一个缓存从来没命中过**

> 我写了个判分缓存。它有文件、在被写、长度在长 —— **看起来完全正常**。
> 后来发现它的键用了 Python 的 `hash()`,而它对字符串**每个进程加随机盐** ——
> 所以那个缓存**一次都没命中过**。
> 修完之后我加了一条:让缓存自己报命中率。**静默的机制要让它出声。**

**故事三:一个 100% 的规则,我造了一批新题去撞它**

> 我给一条规则量出"报了的全对 = 100%"。
> **但这个数是我在【自己设计的题】上量的** —— 那不叫规则好,那叫记住答案。
> 所以我造了一批没参与设计的题去撞。
> 结果是:**精确率确实没掉,召回率只有 67%。**
> **从那以后,"我的系统准确率 X%"这句话,我得先回答三个问题:**
> **在什么条件下量的 / 测的是对不对还是看不看得出来 / 换个数据还成立吗。**

**★★ 故事四:我量了那把给分的尺子**

> 系统跑到 60/60 的时候,我做了一件不太常见的事:
> **去量【判分那把尺子】本身。**
>
> 方法很土:拿**同一批答案**,让判分跑三次。
> ```
> 第1次 判错 [46, 48]
> 第2次 判错 [46, 47, 48]
> 第3次 判错 [40, 46, 48]
> ```
> **同一批答案,三次判出来的错题不一样。**
>
> 查下去,原因不在模型,在**判据有三个洞**:
> "关键事实一致就算一致"没写清——名字对、数字没给,算不算一致?
> "多说了别的,不算错"——**那【少说了】呢?也没写。**
>
> 把洞补上,判分从【晃 ±1】变成【完全不晃】:58/57/57 → **59/59/59**。
>
> **而这件事最值的地方不是那个结果,是它推翻了一个我本来会犯的错:
> 在量准之前,我不敢说"我的系统 60/60"——
> 因为我不知道那个 60 里,有多少是判分给的面子。**

**★ 中间如果被追问,还有一条可以提(第 12 课):**

> 我照着一个失败案例做了个重试循环。做完发现:
> **那个动作的依据,建立在一个【已经作废的实验】上** ——
> 提示词改过之后,原来那个现象就不出现了。
> 重新量了一遍,发现那个动作**不但没用,还有害** —— 于是自己把它删了。
> **"自己写的东西,自己验出来该删" —— 这件事我想讲。**

**收尾:**

> 现在:**60/60,静默失败 0 道,报告里每个数都能核 ——
> 而这份报告的第一节,写的是【它的可信程度】。**
>
> **★ 而那个 60,是【先把判分校准过】之后量的。**
> **因为用户的损失不是"数字错了",是他不知道自己手上那个数字是错的 ——
> 而如果连量数字的尺子都不准,你连这句话都没资格说。**

## 十二、诚实栏(这一栏最该背)

**能说清自己边界的项目,比说"我 95%"的可信。**

**★ 先看这一条 —— 它最容易被念成一个好看的数字,而它其实是个限制:**

```
· 现在 60/60(第 12 课之后)
  ★★ 但"60/60"意味着【这 60 道题已经用尽了】:
     改什么都不变 —— 它现在只能当【回归测试】(改坏了没有),
     量不出进步了。
  ★★★ 而要量进步,得【出新题】(那要人来出)或者【换尺子】。
```

**旧的那几条(第 8 课留下的,仍然成立):**

```
· 一条规则有已知的洞:只认「XX万级」,不认「XX万」
· 报告的硬查有假阳性:会把「第 1 名」里的 1 报成"数据里没有的数"
· 来源分两种:人翻 PDF 核 ✅ / 程序追溯 ⚠ 只有进了库的页能
· 年度报告没入库(文件名里没有季度编号,切片时被跳过)
· 60 道题够不够?—— 我知道要造挑战集,也造了,但样本太小(4 道)
```

**★★ 第 9~12 课【新留下的边界】:**

```
【第 9 课】
· 「关键词对·向量错」只在【没有期次过滤】时出现 —— 条件明确,但样本只 4 例
· "位置效应"(两头的材料看得见、中间看不见)—— ★ 14 道里只有 1 道,是个孤例
· "给几页最好"这个旋钮 —— 量出来【分不清】,不是"没调好"

【第 10 课】
· ★ "内容忠不忠实"那一层,【没有尺子】。
  我试过一把字面的,修了四次,每次都把"格式差异"当成"内容差异"
  (页码漂 / 一个空格 / 改写 / 全角半角)—— ★ 最后发现:
  "照抄才算有据"这条判据,和"生成"这件事【天生冲突】,因为生成就是重组材料。

【第 11 课】
· 判分的不稳定度只量了两批,每批只有 3 次 —— 要给一个可靠的数,得跑更多次
· ★ "数字和专名必须齐"这条规则,是我提的、人点头的;
  但点头的时候只看到"它比上一版好",没看到全部证据。
  **这不算他独立判断过。**

【第 12 课】
· 循环【只验过一种动作形态】("算出来补",一次到位)。
  另一种("再来一轮")写出来过,但实测后删了 —— 它从没被真正触发过
· diagnose 只认 2 类失败;循环上限 3 是【照抄业界的】,没自己量
· 成本上限没做:每多一轮 = 多一轮大模型调用
```
