## 一、基线数字

判分在 `tools/score_eval.py`,评估集在 `docs/评估集.xlsx`(60 道)。

```
去向对          52/60        ← 该走 SQL / 检索 / 拒答,走对了没有
全对            32/60        ← 去向对 且 答案满分
机器判不了       0/60        ← 机器核不了的,单独一档,不算错
两项全对        32/60
★ 平均得分     37.150/60 = 61.9%   ← 口径②:复合题按子项给分,[0,1] 连续值
```

**按类别**(全对 / 总数,平均得分):

| 类别 | 全对 | 平均分 | 题数 |
|---|---|---|---|
| 数值·单点 | 6/8 | 0.81 | 8 |
| 数值·比较 | 1/8 | 0.58 | 8 |
| 数值·排名 | 5/5 | 1.00 | 5 |
| 数值·指标 | 6/6 | 1.00 | 6 |
| 拒答·双向 | 8/10 | 0.80 | 10 |
| **叙述·检索** | **2/15** | **0.13** | 15 |
| 边界·刁钻 | 4/8 | 0.62 | 8 |

**拒答两个方向分开看**(张君杰要求,不能合并):

```
该拒的   5/8 拒对了      ← 拒错了比答错更贵:用户拿不到数据,而且不会知道
该答的  47/52 没被误拒   ← 拒多了同样是错。拒答不是最安全的选项
```

## 二、这个基线是怎么算出来的

```bash
python tools/check_eval.py          # 先核对评估集本身(60/60 可核,0 分歧)
python tools/score_eval.py          # 再拿评估集去问系统 → docs/评估集_跑分.json
python tools/score_eval.py --from-json   # 不重跑调用,直接拿存下的答案重判分
```

**大模型判分有缓存**(`docs/评估集_判分缓存.json`)。重跑时命中缓存的题不重新调用。
⚠ 改了评估集里的【期望答案】,缓存键就变了,那几道会重新调用。

## 四、改参数的规矩(防止"是撞运气赢的")

1. **一次只改一个变量。** 同时改三处,分数涨了也不知道是谁的功。
2. **每次改完重跑全部 60 道**,不是只跑相关的那几道 —— 你可能修好一类、弄坏另一类。
3. **看类别分数,不看总分。** 总分涨 2 个点可能是"叙述检索涨了 0.5、数值比较跌了 0.3"。
4. **改完要能说出"我预期哪一类会涨、涨多少"。** 说不出来就说明这次改动是瞎试。
   预期落空比分数难看更有信息量 —— 那说明你对系统的理解和系统不一样。
5. **不许改评估集来让分数变好看。** 评估集动了,基线就废了,得从头再来。
6. 每一轮的结果**追加**记到 `docs/第7课实验台账.md`,不覆盖 —— 失败的尝试也要留。
